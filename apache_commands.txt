0) Connect & update

# become root or use sudo for each command. I'll use sudo below.
sudo apt update
sudo apt install -y apache2 apache2-utils

1) Back up existing Apache configs (do this first)

sudo mkdir -p /root/apache-backups
sudo cp -a /etc/apache2 /root/apache-backups/apache2-$(date +%F-%T)
ls -l /root/apache-backups

2) Show & (optionally) replace entire /etc/apache2/apache2.conf

You usually do not need to replace the global apache2.conf — changing the site config is enough — but since you asked for entire config files, here is a recommended full apache2.conf you can use. If you already have one, make sure the default Directory settings don't force AllowOverride None. The file below is the canonical-ish Ubuntu 22.04 apache2.conf content with a Directory /var/www/ block set to allow overrides for .htaccess.

Backup done above. To overwrite with the version below:

sudo tee /etc/apache2/apache2.conf > /dev/null <<'EOF'
# This is a full apache2.conf suitable for Ubuntu 22.04
# See /usr/share/doc/apache2/README.Debian for more information.

Mutex file:${APACHE_LOCK_DIR} default

PidFile ${APACHE_PID_FILE}

Timeout 300

KeepAlive On

MaxKeepAliveRequests 100

KeepAliveTimeout 5

User ${APACHE_RUN_USER}
Group ${APACHE_RUN_GROUP}

HostnameLookups Off

ErrorLog ${APACHE_LOG_DIR}/error.log
LogLevel warn

IncludeOptional mods-enabled/*.load
IncludeOptional mods-enabled/*.conf

Include ports.conf

# Global configuration
<Directory />
    Options FollowSymLinks
    AllowOverride None
    Require all denied
</Directory>

# DocumentRoot directory -- allow .htaccess in /var/www
<Directory /var/www/>
    Options Indexes FollowSymLinks
    AllowOverride All
    Require all granted
</Directory>

<Directory /usr/share>
    AllowOverride None
    Require all granted
</Directory>

<Directory /var/www/html>
    Options Indexes FollowSymLinks
    AllowOverride All
    Require all granted
</Directory>

# Access file names
AccessFileName .htaccess

# The following lines are default Debian includes
IncludeOptional conf-enabled/*.conf
IncludeOptional sites-enabled/*.conf
EOF

(If you prefer not to overwrite apache2.conf, skip the tee step — but ensure your existing Directory /var/www block has AllowOverride All.)
3) Replace the site config: /etc/apache2/sites-available/000-default.conf

This is the full default virtual host for port 80. It contains a <Directory> block for /var/www/html with AllowOverride All so .htaccess is honored.

sudo tee /etc/apache2/sites-available/000-default.conf > /dev/null <<'EOF'
<VirtualHost *:80>
    # ServerName example.com
    ServerAdmin webmaster@localhost
    DocumentRoot /var/www/html

    # Full directory block so .htaccess works
    <Directory /var/www/html>
        Options Indexes FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>

    # Logs
    ErrorLog ${APACHE_LOG_DIR}/error.log
    CustomLog ${APACHE_LOG_DIR}/access.log combined

    # Uncomment to set a specific ServerName:
    # ServerName your.domain.or.ip
</VirtualHost>
EOF

If you also use HTTPS /etc/apache2/sites-available/default-ssl.conf exists; we’ll leave that untouched for now.
4) Enable mod_rewrite and other helpful modules

.htaccess commonly uses mod_rewrite and mod_headers. Enable them:

sudo a2enmod rewrite
sudo a2enmod headers
sudo systemctl restart apache2

5) Test Apache configuration syntax before restarting full service

sudo apache2ctl configtest
# you should see: Syntax OK

If it prints errors, do not restart — fix the syntax. If Syntax OK, restart:

sudo systemctl restart apache2
sudo systemctl status apache2 --no-pager

6) Create a sample site document root and index (if not present)

sudo mkdir -p /var/www/html
sudo chown -R www-data:www-data /var/www/html
sudo chmod -R 755 /var/www/html
sudo tee /var/www/html/index.html > /dev/null <<'EOF'
<!doctype html>
<html>
<head><meta charset="utf-8"><title>Apache on Ubuntu 22.04</title></head>
<body>
<h1>It works — Apache with .htaccess enabled</h1>
<p>If you can see this page, Apache is serving /var/www/html</p>
</body>
</html>
EOF

7) Create the .htaccess file (full file contents)

Place this example in /var/www/html/.htaccess. It includes:

    disabling directory listing

    a simple rewrite that redirects non-https to https only if you have SSL (I include it commented and uncommented options)

    a tiny friendly rewrite test

sudo tee /var/www/html/.htaccess > /dev/null <<'EOF'
# Example .htaccess for /var/www/html

# --- Basic server rules ---
# Turn the rewrite engine on
RewriteEngine On

# Example: simple rewrite test — redirect /test to / (temporary)
RewriteRule ^test/?$ / [L,R=302]

# Deny directory listing
Options -Indexes

# --- Optional HTTPS redirect (only enable if you have an SSL cert configured) ---
# If you ARE using SSL and have enabled the SSL site, uncomment these lines:
# RewriteCond %{HTTPS} off
# RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
#
# If you are NOT using SSL, leave the HTTPS redirect commented out.

# --- Optional basic deny/allow example ---
# Deny access to .env files
<FilesMatch "^\.env">
    Require all denied
</FilesMatch>
EOF

Set ownership and perms:

sudo chown www-data:www-data /var/www/html/.htaccess
sudo chmod 644 /var/www/html/.htaccess

8) Test .htaccess behavior

    Confirm .htaccess is being read by making a rule that should break the site if active (or use the rewrite test above).

    Use curl to see response codes:

# Test rewrite rule (should be a 302 redirect to /)
curl -I http://localhost/test

# If you are testing from another machine, substitute your server's IP/domain:
# curl -I http://your.server.ip/test

If you get a 302 redirect to /, the rewrite ran: .htaccess is active. If you get 200 and the content, check /var/log/apache2/error.log for errors:

sudo tail -n 200 /var/log/apache2/error.log

9) Optional: Password protect a directory with .htaccess + .htpasswd

    Create a directory to protect (example /var/www/html/secure):

sudo mkdir -p /var/www/html/secure
sudo chown -R www-data:www-data /var/www/html/secure
sudo tee /var/www/html/secure/index.html > /dev/null <<'EOF'
<html><body><h1>Protected area</h1></body></html>
EOF

    Create an htpasswd file with apache2-utils (already installed earlier). Store it in /etc/apache2/.htpasswd (outside webroot):

# create user "alice" (will prompt for password)
sudo htpasswd -c /etc/apache2/.htpasswd alice
# to add more users later: sudo htpasswd /etc/apache2/.htpasswd bob
sudo chown root:www-data /etc/apache2/.htpasswd
sudo chmod 640 /etc/apache2/.htpasswd

    Add an .htaccess to the protected directory that points to that passwd file:

sudo tee /var/www/html/secure/.htaccess > /dev/null <<'EOF'
AuthType Basic
AuthName "Restricted Content"
AuthUserFile /etc/apache2/.htpasswd
Require valid-user
EOF

sudo chown www-data:www-data /var/www/html/secure/.htaccess
sudo chmod 644 /var/www/html/secure/.htaccess

    Test by accessing http://your.server.ip/secure/ in a browser — it should prompt for credentials.

10) UFW / firewall (if you use ufw) — allow web traffic

# Check ufw status
sudo ufw status

# Allow HTTP and HTTPS
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
# Then reload/status
sudo ufw reload
sudo ufw status

11) Troubleshooting checklist

    apache2ctl configtest returns Syntax OK.

    Check logs: sudo tail -f /var/log/apache2/error.log

    Ensure AllowOverride All appears in the <Directory /var/www/html> block of the loaded site config (I set it above).

    Ensure .htaccess is readable by the Apache user: sudo chown www-data:www-data /var/www/html/.htaccess and chmod 644.

    Confirm mod_rewrite is enabled: sudo a2enmod rewrite (re-run if unsure), then sudo systemctl restart apache2.

    If you get 500 errors, temporarily remove/comment .htaccess to confirm error is from its content; then check error.log for the specific reason.

12) Restore backup (if something goes wrong)

If you made the replacements above and want to restore the original config you backed up:

# Assuming you want to restore the most recent backup
sudo cp -a /root/apache-backups/apache2-*/etc/apache2/* /etc/apache2/
sudo systemctl restart apache2
